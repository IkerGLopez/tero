# Cambios — 2026-07-13 (FINAL)

## Resumen

Se corrigieron los errores `"Error al subir el archivo"` que ocurrían durante la indexación masiva de corpus en la herramienta Docs de Tero. **Resultado: 0 errores en 5,521 documentos** (agentes 10, 11 y 12).

## Diagnóstico

### Causa raíz

LangChain `SQLRecordManager.aupdate()` lanza `AssertionError("Time sync issue")` cuando múltiples llamadas concurrentes a `aindex()` con `cleanup="incremental"` compiten por el mismo namespace del record manager. El `aupdate()` compara `CURRENT_TIMESTAMP` de PostgreSQL contra `index_start_dt` y falla si otra transacción concurrente commiteó registros con timestamps posteriores.

Este `aupdate()` se ejecuta **siempre** dentro de `aindex()`, sin importar los parámetros `force_update` o `cleanup`. Es imposible evitarlo desde fuera de LangChain.

### Lo que NO era

- ❌ Rate limiting del LLM — `skipDescriptions=true` durante indexación, el LLM no se invoca
- ❌ Deadlocks de PGVector — aunque existen, no eran la causa principal
- ❌ Pool de conexiones agotado — el semáforo de tareas lo previene

## Cambios realizados

### 1. Semáforo por agente en `aindex()` (`tools/docs/tool.py`)

```python
# Dict module-level, keyed by agent_id
_index_semaphores: dict[int, asyncio.Semaphore] = {}

# En _handle_file(), cuando skipDescriptions=True:
sem = _index_semaphores.setdefault(self.agent.id, asyncio.Semaphore(2))
async with sem:
    await aindex(..., force_update=True)
```

**Motivación**: Serializa `aindex()` por agente, evitando que llamadas concurrentes compitan por el record manager. `Semaphore(2)` permite algo de paralelismo manteniendo el time sync bajo control.

### 2. Semáforo de tareas (`agents/tool_file.py`)

```python
_TASK_SEMAPHORE = asyncio.Semaphore(10)

async def _add_tool_file(...):
    async with _TASK_SEMAPHORE:
        async with AsyncSession(...) as db:
            ...
```

**Motivación**: Limita a 10 tareas de background concurrentes, evitando agotar el pool de conexiones de BD (DB_POOL_SIZE=20 + overflow=30).

### 3. Reintentos automáticos con `error_reason` (`agents/tool_file.py`)

Tres capas de manejo de excepciones en `_add_tool_file()`:

| Handler | Dispara con | Acción | `error_reason` |
|---|---|---|---|
| `SQLAlchemyError` + asyncpg cause | Deadlock (40P01) o serialization (40001) | 1 retry (5s) | `DB_DEADLOCK`, `DB_SERIALIZATION`, `RETRY_FAILED` |
| `AssertionError` + "Time sync" | LangChain time sync | 1 retry (5s) | `TIME_SYNC` |
| `Exception` genérico | Cualquier otro error | Sin retry | `TIME_SYNC` si el mensaje contiene "Time sync" |

Los paths de `raise` setean `error_reason` antes de propagar (`DB_ERROR`, `ASSERTION_ERROR`).

### 4. Campo `error_reason` en `File` (`files/domain.py`)

```python
# File model
error_reason: Optional[str] = Field(default=None)

# FileMetadata (API)
error_reason: Optional[str] = None
```

**Motivación**: Permite diagnosticar por qué falló un archivo desde la API, sin necesidad de acceder a logs del servidor.

### 5. Retry loop en el runner (`scripts/rag_eval/runner.py`)

Después de la indexación inicial, el runner detecta archivos en ERROR y los re-subí secuencialmente (hasta 3 intentos, 2s entre cada uno). Trackea los nuevos `file_id` de cada re-upload y espera sobre ellos.

```python
for attempt in range(1, 4):
    error_files = await tero.list_error_files()
    fresh = [(fid, name) for fid, name in error_files if fid not in prior_errors]
    if not fresh: break
    for fid, name in fresh:
        idx = int(name.removeprefix("doc_").removesuffix(".txt"))
        new_fid = await tero.upload_document(name, corpus[idx].encode("utf-8"))
        retry_ids.append(new_fid)
        await asyncio.sleep(2)
    await tero.wait_files_processed(retry_ids)
    prior_errors.update(fid for fid, _ in fresh)
```

**Motivación**: Los errores de time sync son transitorios — al reintentar sin concurrencia, procesan correctamente.

### 6. `list_error_files()` en el client (`scripts/rag_eval/tero_client.py`)

Devuelve `list[tuple[int, str]]` con `(id, name)` de archivos en ERROR, permitiendo al runner extraer el índice del documento desde el nombre.

### 7. Seed de `gpt-4o-mini` en tests (`tests/assets/init_db.sql`)

Agregado el modelo `gpt-4o-mini` al seed de la BD de pruebas para que coincida con el `.env` de producción.

### 8. `error_reason` en `FileMetadata` (`files/domain.py`)

Expone el campo en las respuestas de la API para diagnóstico.

## Lecciones aprendidas

- `ToolRepository()` crea nuevas instancias por llamada → los semáforos de instancia no funcionan; deben ser module-level
- `aindex()` de LangChain siempre ejecuta `aupdate()` con chequeo de timestamp; `force_update` y `cleanup` no lo previenen
- El build de Docker estaba roto (sass/pnpm) → se usó `docker compose cp` para desplegar
- Judgment Day (3 rondas) encontró bugs reales que los tests de integración no cubrían
